# POFlow v1.3 — الاختبار ومعايير القبول

## 1 · اختبارات القبول على الخادم (Node، بدون إنترنت)
`tests/gas-mock.js` يحاكي خدمات Apps Script (Sheets · Drive · Properties · Cache · Lock · Session · Utilities · Mail) ويشغّل **Code.gs الحقيقي دون تعديل**.
التوقيعات تُشفَّر بنفس خوارزمية المتصفح (WebCrypto: PBKDF2 310,000 + AES-256-GCM).
```
node tests/acceptance.test.js
```
| المجموعة | ما يُختبر |
|---|---|
| 0 | الدخول للنطاق فقط، RBAC في الخادم، تسجيل 5 توقيعات مشفّرة، عدم وجود صور واضحة في السجل |
| A | إنشاء ← توقيع الجهة ← المشتريات (رقم تسلسلي + 3 موقّعين + «يعلم») ← تسلسل صارم ← منع التوقيع خارج الدور والتكرار ← اعتماد ← PDF ← بريد بالمرفق للمشتريات والجهة والموقّعين و«يعلم» ← التحقق بالرمز وبالبصمة ← صلاحية المدقق للقراءة فقط |
| B | رفض عند الموقّع الثاني: سبب إلزامي، إيقاف الدورة، إشعار المشتريات والجهة الطالبة، **عدم إرسال الطلب للموقّع الثالث**، منع الاستئناف، نسخة 1.1 مع بقاء 1.0 |
| C | الإعادة للاستكمال، المرفقات بالبصمة، التفويض «بالنيابة عن»، التذكير والتصعيد، اكتمال سجل التدقيق، الإشعارات |

النتيجة الحالية: **72/72 ✔**

## 2 · اختبار المتصفح (Chrome headless + Index.html الحقيقي)
`tests/e2e-server.js` يقدّم الصفحة عبر `doGet` ويربط `google.script.run` بالخادم المحاكي.
```
npm i jspdf@2.5.1 qrcode-generator@1.4.4 lucide@0.453.0     # مرة واحدة (مجلد LIB)
node tests/e2e-server.js 8787 &
python3 tests/e2e.py <LIB>/node_modules <OUT>
```
يمر بالسيناريوهين من الواجهة نفسها: تعبئة النموذج، تسجيل التوقيع ورفع صورته وتشفيرها في المتصفح، التوقيع بالرقم السري، اقتراح المسار من مصفوفة الصلاحيات ودليل المناصب، بدء الدورة، 3 توقيعات بالتتابع، إنشاء PDF النهائي في متصفح آخر موقّع (jsPDF)، الأرشفة والبريد، صفحة التحقق، ثم الرفض عند الموقّع الثاني.
النتيجة الحالية: **29/29 ✔** — اللقطات في `docs/screens/` والملف الناتج في `docs/sample-approved-PR-2026-0001.pdf`.
